A compiler from programs to training runs

Halting Descent

Give this compiler any Turing machine and it returns a neural network and a starting point. Run ordinary gradient descent on it and the weights execute the program, one machine step per gradient step. The loss reaches zero on the exact step the program halts.

The largest run here sits on a flat loss plateau for 47,176,869 steps and converges on step 47,176,870. That number is the fifth Busy Beaver, the longest any 5-state program can run before stopping, proved in 2024. Nothing in the loss curve before that step tells you it is coming.

How it works

The trainable vector z holds the tape, a one-hot head position, and a one-hot control state. A frozen ReLU network f maps any such vector to the machine's next configuration. Its first layer is a hard threshold, flat everywhere except a narrow band around 0.5. The loss is the squared distance between z and f(z).

net, z0 = compile_machine("1RB1LC_1RC1RB_1RD0LE_1LA1LD_1RZ0LA", N=12400)
z   = torch.nn.Parameter(z0)
opt = torch.optim.SGD([z], lr=1.0)
while True:
    loss = 0.5 * (z - net(z)).pow(2).sum()
    if loss == 0: break            # the program has halted
    opt.zero_grad(); loss.backward(); opt.step()

Away from the threshold band f is locally constant, so the gradient is exactly z − f(z) and a step of size 1 lands on the next configuration. A halted machine is a fixed point of f, which makes it a global minimum with loss 0. A program that never halts gives a training run that never converges.

Whether a compiled run ever reaches zero loss, given enough tape, is the halting problem. No test on the loss curve, the gradient norm, or the weights can answer it in general.

What was checked

  • For the 2-, 3- and 4-state Busy Beavers, torch.optim.SGD reproduces the reference machine at every step, autograd's gradient equals z − f(z) with zero error, and the loss first hits 0 on steps 6, 21 and 107.
  • The 47-million-step runs use a dense C implementation of the same update. It was compared against PyTorch autograd over steps 1,000,000 to 1,002,000 and from step 47,175,000 to the halt; the weight vectors match bit for bit.
  • A program that never halts was run for 20,000 steps; the loss never dropped below 1.

What is new and what is not

The idea that gradient descent can simulate a Turing machine is not new. Welper (2020) constructs loss functions whose descent steps trace a machine's steps, and Chatziafratis, Roughgarden and Wang (2018) show online gradient descent can encode polynomial-space computation. Recurrent networks have been known to be universal since Siegelmann and Sontag in the 1990s.

What I could not find elsewhere is the working object: a compiler you can run, a real training run that executes the fifth Busy Beaver to its proven halting step, and measured tolerance to learning rate and gradient noise. The network is also built for the purpose. The weights being trained are the program's memory, and the network that reads them is frozen. This says nothing about what happens when a language model is trained on data.
